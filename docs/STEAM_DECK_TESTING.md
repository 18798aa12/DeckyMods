# Steam Deck 实机验收

当前的本地自动测试使用临时游戏目录和合成文件，不能证明游戏内 MOD 已生效。建议先用一个容易验证、无额外依赖的剑星 PAK MOD，再测试 REFramework 脚本。

1. 记录 SteamOS/Decky 版本。插件须普通 deck 用户运行，系统可加载 libarchive。不要为安装插件关闭 SteamOS 只读保护或设 root 标记。
2. 在 Decky 从 ZIP 安装后，打开插件，确认界面、游戏目录与本机 Steam/SD 卡安装位置一致。
3. 验证控制器焦点、输入框、屏幕键盘、文件选择器返回；B 的第一次提示及第二次返回需在游戏模式测试。
4. 将合成小 ZIP 放在 Downloads，导入并查看预览；先不写入真实游戏。检查错误包、可选目录或未适配游戏有明确提示。
5. 在选定的真实游戏退出后，安装一个本人下载的已知兼容 MOD。核对前置、版本和作者说明，在游戏里验证效果。
6. 退出游戏，禁用 MOD，验证游戏恢复；启用后再次验证；卸载并确认恢复。涉及同名文件的两个 MOD 还应验证层覆盖恢复。
7. Steam 正在下载/验证游戏、游戏运行中应阻止修改。外部工具改了已管理文件时必须提示冲突，保留外部内容和备份。
8. Nexus 普通账户：本人绑定个人 Key；文件页面确认下载；允许 NXM 接收，核对任务进入检查/预览。默认协议关联需可恢复。浏览器无 NXM 下载入口时使用本地导入。
9. 查看私有设置目录权限：目录 0700，账户/任务文件0600。勿把该目录或 NXM 授权链接发到公共 issue。

代码故障注入已覆盖写入中断、交换后中断、恢复再次中断、目标或祖先链接替换，以及备份后 Steam 更新竞态。不要用真实游戏主动拔盘/断电复现这些场景。

SSH 可只在本地测试期间启用：`sudo systemctl start sshd`；结束后可执行 `sudo systemctl stop sshd`。连接授权与账户密码由设备本人管理。
